## 1. Review 结论

方向可行，但初稿缺少足以安全自动推进任务的行为约束。本轮从极端条件、边界、时序、用户操作、数据隔离、可拓展性和可迭代性检查，形成下面 14 组修订。

本轮“已处理”指需求规则已明确并获确认，不代表问题已经由代码修复或通过运行时验证。下一阶段需要把这些规则落实到技术方案和验收测试。

- **P1**：可能导致错误投递、错误成功、执行串用、数据损坏或越界读取，必须在第一版方案中处理。
- **P2**：影响兼容性、可恢复性、使用体验或演进，同样需要在第一版明确行为和限制。

## 2. 发现与修订

### F01 · P1 · 混用任务、agent 和控制权状态

- **触发**：agent 空闲但无结果；已经写出结果但仍在运行；执行中等待审批。
- **后果**：误报任务成功、过早释放占用、把下一项输入发到错误交互阶段。
- **明确规则**：任务阶段、agent 观测、连接有效性、调度模式及网页控制方分别记录。结果收集与可再次派发分别判断。
- **需求／验收**：R01、R05、R07；V08、V09、V18。

### F02 · P1 · 投递无法实现端到端恰好一次

- **触发**：输入已发送，服务在记录响应前崩溃；部分输入超时；多个页面或服务同时派发。
- **后果**：同一任务被重复执行，或残留输入和重试内容拼接。
- **明确规则**：持久化投递意图在先；单派发者、单执行占用、请求去重；结果不明时待确认，不自动重发。
- **限制**：herdr 的 prompt 请求没有为 Meteor Flow 任务提供执行去重承诺；网页请求去重不能消除所有外部执行不确定性。
- **需求／验收**：R02；V03、V04、V05、V26。

### F03 · P1 · 已有 agent 与网页新建 agent 的就绪条件不同

- **触发**：把 `interactive_ready` 作为统一条件；新建 agent 仍在登录或首次授权；启动超时后再次启动。
- **后果**：可用的已有 agent 永远不能调度，或向初始化界面发任务、重复启动进程。
- **证据**：herdr 0.9.0 的 `managed_agent_interactive_ready` 取决于 `managed_agent` 的 Active 阶段，不是全部 agent 的通用输入就绪标记。
- **明确规则**：新建等待启动流程；已有先观察并确认归属、就绪和隔离。能力不足时只观察，不擅自清理已有环境。
- **需求／验收**：R03；V01、V02、V06、V27。

### F04 · P1 · 名称和终端位置不足以确认执行身份

- **触发**：同一窗格内 agent 退出重启；移动窗格；herdr 重启或恢复会话；投递检查后人工替换 agent。
- **后果**：任务或输入交给错误实例，旧任务占用被错误继承。
- **明确规则**：综合 session、终端及可用会话／进程证据；重连核对身份；不明时暂停。名字和位置仅作显示与定位。
- **限制**：保留原生操作且不修改 herdr 时，检查与写入之间不能获得未经接口支持的全局原子保证。自动调度要求用户配合不替换受管 agent。
- **需求／验收**：R04、R12；V07、V24。

### F05 · P1 · 结果文件存在不代表任务成功

- **触发**：结果写了一半；产物仍变化；旧执行结果迟到；只看到 idle 或进程退出；任务合法地没有文件产物。
- **后果**：不完整数据被发布，错误归属，或有效任务被永久卡住。
- **明确规则**：每次执行独立结果目录，临时写入后原子提交；校验任务／执行标识；收集归档；结合执行结束判断。允许无文件产物。
- **异常处理**：区分业务失败、收集失败和没有结果；不自动追加追问；人工补录须标明来源，不能绕过未停止执行或必需产物缺失。
- **需求／验收**：R05、R11；V08、V09、V10、V13。

### F06 · P1 · 取消、成功、重试及迟到结果缺少顺序规则

- **触发**：取消与成功同时到达；中断未生效便重试；旧执行在新执行后提交结果。
- **后果**：结论反复翻转、两个执行并存、文件相互覆盖。
- **明确规则**：服务持久化接受顺序决定胜出操作；成功已终态则取消无效，否则取消先被接受后维持取消流程。停止未确认不释放占用、不重试。
- **限制**：取消不回滚文件；重试不是干净环境；中断 agent 不保证结束全部后台进程。成功任务再次执行复制为新任务。
- **需求／验收**：R06；V11、V12、V13。

### F07 · P1 · 队首阻塞及失败后的推进规则不明确

- **触发**：队首等待依赖，但后方独立任务可执行；业务失败与投递不明被相同处理。
- **后果**：队列无故停滞，或在 agent 状态不明时继续投递。
- **明确规则**：从满足条件的任务中按创建顺序选择；业务失败且 agent 可用时可继续独立任务；调度异常暂停受影响队列；不抢占或自动改派。
- **需求／验收**：R07；V14、V15。

### F08 · P1 · 依赖和产物缺少执行版本固定

- **触发**：B 已使用 A 的结果后 A 被重做；执行中修改依赖；删除上游；创建循环。
- **后果**：同一次执行的输入变动、下游不可追溯、永久等待。
- **明确规则**：禁止循环；执行输入冻结；下游固定上游成功执行及归档；成功任务重做创建新任务；受引用对象不直接删除。
- **需求／验收**：R08；V16、V17、V28。

### F09 · P1 · 多页面、原生终端和自动调度竞争输入

- **触发**：多个页面接管；旧连接补发输入；人工接管期间任务完成；审批已在原生终端处理。
- **后果**：错误按键作用到新任务或其他界面、调度器打断人工操作。
- **明确规则**：控制台内单一有效输入方；失权输入作废；断线不重放；接管暂停派发；异常关闭保持调度暂停，显式恢复。
- **限制**：herdr 直接终端连接的控制权不是所有输入来源的全局锁；不把 blocked 状态封装为可脱离实时终端处理的可靠审批工单。
- **需求／验收**：R09、R04；V18、V19、V20。

### F10 · P1 · 目录、会话和数据隔离缺少明确层级

- **触发**：多个 agent 实际访问重叠目录；跨项目复用会话；下游修改上游产物；共享端口或外部资源。
- **后果**：文件误覆盖、上下文串用、输入污染，或对隔离能力产生错误预期。
- **用户已选择**：独立工作目录与会话，减少误覆盖和上下文串用；不提供同一系统用户下的文件权限隔离。
- **明确规则**：项目归属、独立真实目录与会话、每次执行独立输入／结果／归档、下游使用产物副本。已有实例不满足条件时保持观察。
- **限制**：同一 agent 在同一项目内连续任务可保留上下文；目录分开不等于进程、端口、Git 公共元数据或外部服务隔离。
- **需求／验收**：R10；V17、V21。

### F11 · P1 · 产物采集可能越界或耗尽资源

- **触发**：任意绝对路径、符号链接逃逸、特殊文件、超大文件、采集中文件被修改、恶意预览内容。
- **后果**：读取任务范围外数据、采集阻塞、归档损坏、网页执行不可信内容。
- **明确规则**：仅采集授权范围内显式列出的普通文件；真实路径校验与容量限制；变化时报告收集异常；不可变归档；安全预览且不自动加载外部资源。
- **异常处理**：重试收集不重跑任务；磁盘不足停止新派发。
- **需求／验收**：R11；V09、V22、V23、V25。

### F12 · P1 · 恢复时可能把缺失历史误当成当前事实

- **触发**：休眠、断线、服务崩溃、herdr 重启、事件丢失及乱序观测。
- **后果**：使用旧 idle 继续派发、误判期间成功、遗漏结果或覆盖新状态。
- **明确规则**：标记观测过期；重新订阅并读取当前快照；核对身份、记录和结果文件；恢复扫描；先核对再派发；无法确定时待确认。
- **限制**：快照不能重建断线期间全部历史。时间线标记缺口，不承诺完整终端日志或内部推理记录。
- **需求／验收**：R12；V04、V07、V24。

### F13 · P2 · 超时、负载、磁盘和清理边界不足

- **触发**：长时间思考或等待审批、输出洪峰、慢浏览器、磁盘满、重复启动服务、降低并行上限。
- **后果**：误判卡死、调度被画面阻塞、无记录执行或历史被误删。
- **明确规则**：分阶段超时、不按无输出自动失败；限制缓存和并发；存储不可写不新派发；休眠后核对；不自动删除历史及受引用产物。
- **后续细化**：具体超时、配额、并发默认值及性能目标进入技术设计，需结合实际 agent 行为验证。
- **需求／验收**：R13、R02；V24、V25、V26。

### F14 · P2 · 版本、职责边界和迭代流程不足

- **触发**：把 herdr master 字段用于 0.9.0；对所有 agent 宣称相同能力；升级或恢复旧数据后直接继续派发。
- **后果**：兼容性错误、迁移困难、旧命令重放，后续能力增加需要重写核心业务。
- **已核实**：本机 0.9.0 导出 schema 的 protocol 为 22，包含 `state_change_seq`，没有 `completion_seq`。
- **明确规则**：启动能力检测、按能力开放管理、职责分离、协议及存储版本边界、迁移与恢复计划、session 归属。
- **范围限制**：不提前实现插件平台或远程能力。技术组件、兼容矩阵及实现逻辑需下一阶段单独确认。
- **需求／验收**：R14；V24、V27、V29。

## 3. 不能被本轮设计消除的限制

1. `agent.prompt` 的输入提交与本地任务记录之间不存在跨系统原子事务；结果不明时需人工核实。
2. 保留原生终端和其他输入路径时，不能通过网页控制权阻止所有并发输入。
3. herdr 状态检测存在 agent 与版本差异；空闲、退出、blocked 均不能独立证明业务结论。
4. agent 自报成功不是独立质量验收；第一版不验证所有通用任务的语义正确性。
5. 独立目录和会话不是安全沙箱，不能防止同一系统用户下的越权访问。
6. 已执行的文件修改和外部副作用不会因取消或重试自动撤销。
7. 中断 agent 不等于保证停止全部后台子进程。
8. 断线缺失事件及全部历史终端输出无法保证补回。

这些限制必须在产品行为和技术设计中保持一致，不能通过展示文案掩盖。
