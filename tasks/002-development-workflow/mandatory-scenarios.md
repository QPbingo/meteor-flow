# 六类强制验证场景

状态：用户已确认，2026-10-06；适用范围：每次涉及代码行为的变更。
本文件规定验证义务，不新增产品行为。预期以各任务已确认需求为准；需求含糊时记录缺口，不能由测试自行决定产品规则。

| 类别 ID | 必须分析和验证 | 本地 Agent 控制台需求示例 |
| --- | --- | --- |
| state-transition | 合法/非法转换、终态不被旧事件覆盖、任务/观测/连接/控制状态分离；无结果的空闲不等于成功 | R01、R05、R06；V08、V11、V12、V15 |
| idempotency | 重复请求、事件、重试与响应丢失；断言执行占用、投递、写入等实际副作用次数；幂等作用域不能跨执行尝试误去重 | R03、R04、R06；V03、V04、V06、V26 |
| ordering | 成功/取消竞争的两种先后、过期审批输入、乱序/迟到事件、并发依赖评估；使用可控调度或同步点，不能只 sleep 后观察 | R06、R08、R09；V11、V13、V18、V19 |
| recovery | 副作用前后和记账前后崩溃、重启、休眠、断线、磁盘不足；先核对身份与结果，再恢复调度，不盲重发 prompt/审批输入 | R03、R11、R12、R13；V04、V05、V24、V25 |
| association | task/执行尝试/agent/session/结果/artifacts 所有权、输入快照、依赖关系与删除引用；旧执行不得覆盖新执行 | R04、R05、R08、R11；V07、V09、V13、V16、V17、V28 |
| isolation | 独立真实工作目录和会话、并行上下文不串用、测试数据库/文件/端口资源隔离、越界产物与符号链接；共享资源冲突需显式安排 | R09、R10、R11、R14；V18、V21、V22、V26、V29 |

每类至少明确：适用性及理由、需求/验收编号、具体用例、前置条件、输入和事件顺序、预期状态与副作用、实际结果、证据。
一类有多个用例时全部列出；类结果不能掩盖其中的失败或未执行。适用场景必须有实际执行证据，不能用“代码看起来正确”替代。

不适用只用于变更不涉及该类行为的情况，例如纯文案。仅测试环境不具备、尚未实现、成本较高都不是不适用，应记为 blocked 或 not-run。
后端行为变更不能把六类统一标为不适用。独立审查者复核适用性、需求覆盖与用例强度。

业务约束示例：取消与成功以服务持久化接受顺序判定；旧执行可能存活时不能自动重试；工作目录/会话分离不提供同一系统用户下的权限隔离。
模拟器负责可重复故障注入；真实 herdr 链路另行验证。不能把模拟结果写为真实集成通过。

测试使用专用临时目录、独立数据库/命名空间和动态端口，清理只作用于本次创建的资源。
测试数据不得来自生产数据；测试环境不足时停止相关破坏性用例并报告阻塞。
