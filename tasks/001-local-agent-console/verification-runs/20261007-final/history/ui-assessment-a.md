## 结论与设计特异性

界面已有可信的本机任务工作台基础。顶部连接观测、任务阶段与等待原因、Agent 的观察/自动/手动模式、独立执行尝试与冻结输入，均来自本产品真实工作规则，结构不是仅替换标题的通用后台。低饱和蓝、浅灰画布、中文系统字体和表格符合 Operate 模式；不需要为了“独特”添加装饰。

## 做得好的地方

1. **状态维度分离有清楚的界面承载。** 任务表将等待原因放在名称之下；Agent 页分别显示模式、暂停、确认接入、占用和观测。用户不会把空闲误读为成功。证据：[桌面列表](ui-a-desktop.png)、[Agent 页](ui-a-agents.png)。
2. **高风险行为有及时解释。** 顶部暂停提示说明已开始的执行继续运行；终端说明释放控制不会恢复调度、断线不会补发按键。它们降低对不可逆执行的误解。证据：[只读终端断开状态](ui-a-terminal.png)。
3. **表单的基础可达性良好。** 可见标签与输入关联、首字段有明显焦点、Esc 可退出；高级输出范围折叠，200% 文字放大后可滚动到提交按钮。证据：[表单](ui-a-task-form.png)、[200% 表单底部](ui-a-text-200-form-bottom.png)。

## 优先问题

### A-01 · P1 · 选择任务后，详情在视口外且焦点未跟随

**复现：** 390×844 视口，列表只有两项；点击第一项“核对任务结果和文件产物”。详情确实渲染，但其顶部位于 `y=951.625`，页面 `scrollY=0`，焦点仍在原任务按钮；当前屏幕没有显示新详情。桌面 1440×1000 上同一布局将详情放在整个表格之后，详情顶部 `y=549.59`。列表更长时放在末尾的结构会继续扩大查找距离，后者为源码推断，未伪造千条任务实测。

**影响：** 选择之后看不到变化，用户难以确认是否打开成功。窄屏和键盘用户必须猜测并查找内容位置；查看运行证据这一主任务受到明显阻碍。

**建议：** 保留当前 URL 行为，但选择任务时将详情标题移入视口并给予可见焦点；关闭详情返回原任务按钮。或使用独立详情页面/固定详情区，确保选择与查看形成连续操作。不要仅增加高亮颜色。

**位置：** `App.tsx:43` 在完整 TaskList 之后渲染 TaskDetail；`Tasks.tsx` 的任务按钮只调用 `selectTask`。关联：R01、页面能力 §3.1、技术方案 §12 键盘主流程。证据：[窄屏点击后](ui-a-narrow-selected.png)、[几何与焦点记录](ui-a-evidence.json)。建议能力：`$impeccable harden` / `$impeccable layout`。

### A-02 · P1 · 项目目录错误被提示为连接或存储故障

**复现：** 创建项目，名称填“A 审查无效路径”，目录填 `/private/tmp/meteor-ui-assessment-a-does-not-exist`，提交。弹窗错误为“操作失败，请查看连接与存储状态”，同时页面顶部仍为“本地连接正常”。输入保留，但没有指向“项目根目录”的提示。

**影响：** 用户不知道需要先准备真实目录或修正路径，可能反复刷新连接、检查存储。建立项目是开始使用的必要步骤，这个恢复建议将用户带离实际问题。

**建议：** 将不存在、无权限、不是目录、目录重叠等可预期失败转成具体用户消息，在项目根目录字段附近显示；例如“此目录不存在。请先创建目录，或填写现有目录的绝对路径”。保留本次已存在的输入保留行为。

**位置：** `App.tsx:45` 项目表单；`apps/server/src/http/server.ts:29` 未识别错误走通用提示。关联：R10、DESIGN.md 的“错误保留表单并给出可执行恢复动作”。证据：[错误界面](ui-a-error.png)、[错误及输入保留记录](ui-a-evidence.json)。只读 API 核对项目仍仅一项，未创建无效项目。建议能力：`$impeccable clarify` / `$impeccable harden`。

### A-03 · P2 · 弹窗关闭后丢失键盘操作位置

**复现：** 聚焦“新建任务”，Enter 打开；焦点正确进入 `input[name=title]`。Esc 关闭后 `document.activeElement` 为 `BODY`；下一次 Tab 到“跳到主要内容”，而非原“新建任务”或其后的控件。使用可见/隐藏 locator 等待确认后仍可复现，非截取 React 过渡时刻。

**影响：** 键盘用户每次取消/返回都需要重新穿过导航和全局配置；屏幕阅读器用户也失去返回位置。可绕行，因而列 P2。

**建议：** 共享 Modal 记录实际触发元素，在关闭后恢复焦点；触发元素已被移除时回到相邻合理标题/控件。可使用 Radix Trigger 或明确 `onCloseAutoFocus` 管理；验证 Esc、取消、关闭按钮、成功提交四条路径。

**位置：** `ui.tsx:12–14` 共享 Modal 为受控打开，只有打开自动聚焦逻辑，没有触发器或返回目标。关联：技术方案 §12 键盘主流程与焦点可见。证据：[关闭后下次 Tab](ui-a-keyboard-return.png)、[焦点记录](ui-a-evidence.json)。建议能力：`$impeccable harden`。

## 情绪路径

进入桌面：连接观测和暂停提示让人知道控制台正在做什么，形成安全感。新建：首字段聚焦、有限必填项和可见归属让人有把握。查看：窄屏点击任务却看不到详情，第一次信任低谷出现。异常：目录错误被引导检查连接/存储，再次降低可控感。离开弹窗：Esc 可退出，但焦点回到页首，使操作结尾不够完整。修复应先连接“选择 → 看到结果”和“错误 → 可行动恢复”这两段，再做纯视觉微调。
