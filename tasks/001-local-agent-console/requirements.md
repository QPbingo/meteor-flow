## 1. 目标与范围

### 1.1 产品目标

在本机浏览器中完成以下流程，同时保留 herdr 原有终端操作：

1. 接入已有 agent，或在网页中启动新的 agent。
2. 创建任务、指定 agent、选择简单的前置任务依赖。
3. 在可执行条件满足后，通过 herdr 的 `agent.prompt` 投递任务。
4. 观察运行情况，在网页交互终端中处理审批及追问。
5. 收集明确结果与本地产物，记录任务结论。
6. 向后续任务提供固定版本的上游结果，并继续调度。

第一版服务本机单个用户、一个选定的本地 herdr session。用户指定 agent，系统自动排队；不自动选择角色或改派 agent。任务类型包括代码、调研、文档等具备本地结果交付能力的通用任务。

### 1.2 已确认的范围

- 使用网页任务控制台，不开发原生桌面客户端。
- 使用独立的本地服务适配 herdr，不以修改 herdr 本体为第一版前提。
- 关闭网页不取消任务；本地服务持续运行时继续管理执行，重新打开网页可恢复展示。
- 控制台数据在本地保存，不做云同步、远程机器管理或多用户协作。
- 保留 herdr 原生终端操作，同时提供显式的自动调度与手动使用切换。
- 不同 agent 使用独立工作目录和会话；不提供操作系统级文件访问权限隔离。
- 明确结果正常到达时自动判定任务结论；结果缺失或执行不确定时交给用户处理。
- 支持无环任务依赖，不提供工作流画布、条件分支、循环或自动补偿。

### 1.3 不在第一版范围内

- Langflow 集成、自动规划任务、自然语言调度器及通用插件平台。
- 云端数据同步、远程终端和集群调度。
- 独立容器或强沙箱、多租户权限体系。
- 自动 Git worktree 管理、文件修改回滚、运行中任务抢占。
- 对所有 agent 统一解析审批界面并提供统一批准按钮。
- 完整恢复 agent 内部推理、全部历史终端输出或断线期间的事件。

“本地使用”指控制台及其数据的范围，不代表所管理的 agent 不会调用自身配置的模型服务。

## 2. 核心概念

| 概念 | 含义及边界 |
| --- | --- |
| 项目 | 工作目录、agent、任务和输入数据的逻辑归属；不是复杂项目管理系统 |
| Agent 绑定 | Meteor Flow 对一个 herdr 执行实例的管理记录，包含项目归属、身份依据、调度模式和当前占用 |
| 任务 | 用户要完成的工作，包含说明、指定 agent、依赖和结果要求 |
| 执行尝试 | 一次具体执行；重试产生新的执行标识，不能覆盖旧记录 |
| 最终结果 | 当前执行明确提交的成功或失败声明、摘要及产物列表 |
| 产物 | 已完成校验并归档的文件快照；保留来源执行和被下游使用的关系 |
| 观测状态 | herdr 对 agent 的当前判断，不能直接作为业务结论 |

## 3. 页面与用户流程

### 3.1 页面能力

- 任务列表：创建、查看、修改尚未开始的任务、指定 agent、设置依赖、重试、取消及归档。
- Agent 列表：发现与接入已有 agent、启动 agent、查看状态与项目归属、切换调度模式。
- 任务详情：展示冻结的执行输入、当前阶段、等待原因、操作记录、实时终端、结果和产物。
- 网页终端：默认只读；用户接管后输入，释放后恢复观察。只读访问不能改变实际终端尺寸。

### 3.2 基本使用流程

1. 用户选择本地 herdr session，建立项目及 agent 归属。
2. 用户接入或启动 agent，完成就绪和隔离检查后启用自动调度。
3. 用户创建任务并指定 agent；可选择同项目内的前置任务。
4. 系统显示真实等待原因；满足条件后派发。
5. 需要审批或回答时，用户在网页终端或手动使用模式下的原生终端处理。
6. 系统收集最终结果及产物，结束任务，并按依赖和队列规则推进。
7. 发生不确定情况时暂停受影响的自动推进，用户查看证据后决定等待、补录结论、取消或重试。

## 4. 已确认的行为规则

### R01. 分离任务、观测、连接、调度和控制状态

- 任务阶段需要区分待派发、投递中、执行中、结果收集中、取消中、待确认，以及成功、失败、取消等终态。
- 等待依赖、等待人工、手动使用、连接不可用等作为明确原因展示，不能全部简化成“排队”。
- agent 的 `working`、`idle`、`blocked`、`unknown` 与任务结论分开保存。`done` 也不代表业务成功。
- 连接是否实时、最后确认时间、自动或手动模式、网页输入控制方分别记录。
- 有最终结果不表示 agent 已可接受下一项；agent 空闲也不表示任务有有效结果。
- `blocked` 提示可能需要人工处理，不将其一律认定为审批请求；识别不到的情况允许用户主动接管。

### R02. 投递去重与不确定操作

- 同一 agent 同时最多有一个当前执行占用；同一任务最多有一个当前活动执行尝试。
- 同一份本地数据只允许一个调度服务负责派发，多个网页不产生多个调度器。
- 创建执行记录和“投递中”记录必须先于调用 `agent.prompt`。
- 重复点击或重复请求应复用同一有效操作，不能创建重复派发。
- 投递成功仅表示输入提交成功，不能据此判定任务已开始或完成。
- 超时、部分输入、连接中断或服务崩溃导致投递结果不明时，进入待确认并暂停该 agent 队列，不自动重发。
- 人工决定重试前，应核实旧任务是否仍执行及输入框是否有残留内容；不自动清空用户输入。
- 第一版不承诺端到端恰好执行一次；承诺对可识别重复去重，对不确定操作停止自动推进。

### R03. 启动与接入已有 agent

- 新建 agent 必须先准备可用窗格和独立工作目录，再启动所选类型；启动与任务派发是两个阶段。
- 登录、首次授权、初始化或启动失败进入待处理，不能继续向启动界面投递任务。
- 启动超时不代表没有启动；再次启动前先核对真实进程与窗格状态。
- 已有 agent 默认以观察模式接入，确认目录、会话归属、没有未完成工作及符合隔离要求后，才允许启用调度。
- 不自动清空已有会话、改变其工作目录、结束其任务或接管其输入。
- 不能将 `interactive_ready` 作为所有已有 agent 的统一门槛；它在 herdr 0.9.0 中来自托管启动流程。
- 无法可靠识别、派发或提交约定结果的 agent，只允许观察及手动操作，明确展示限制。

### R04. 执行身份与原生终端竞争

- 绑定身份综合 herdr session、终端身份、可获得的 agent 会话和进程证据；名字及窗格位置不能作为唯一身份。
- 识别到 agent 被替换后，新实例不自动继承旧实例的当前执行和调度授权。
- 移动窗格时更新定位信息，不能因此把旧执行绑定到其他 agent。
- herdr 重启或断线后无法证明身份连续性时，暂停自动推进并转待确认。
- 投递前重新核对身份、状态与管理模式，但不宣称检查和终端输入之间具备 herdr 未提供的原子保证。
- 自动调度期间，用户不应在原生终端替换该 agent 或投递其他独立任务；开展手动工作前切换到手动使用模式。
- 这属于配合式管理，不能保证阻止所有来自原生终端或其他 API 调用者的并发输入。

### R05. 最终结果与完成判定

- 每次执行约定一个专用结果提交目录。结果至少表达任务标识、执行标识、成功或失败、摘要及产物列表。
- agent 先写临时结果文件，完整写入后原子提交最终文件；文件名、协议版本和具体报文在技术设计中确定。
- 只接受匹配当前执行的有效最终结果。旧执行的迟到结果归入旧执行，不能覆盖当前结果。
- 最终结果、产物完整归档和本次执行结束的观测共同决定自动终态；单独出现空闲或进程退出不构成成功。
- 结果已经收到但 agent 仍在工作时，可展示已收到结果，不能据此释放占用或派发下一项。
- 不需要文件产出的任务允许产物列表为空；需要的产物以任务明确要求及最终声明为准。
- 区分 agent 明确报告失败、结果收集失败和没有结果。后两者不能直接推断业务失败或成功。
- 缺少有效结果时，不自动向 agent 追加“再总结一次”等新输入。
- 用户可以等待、补录结论、重试或取消；补录记录人工来源、原因与关联证据。
- 自动成功表示 agent 明确报告成功，不表示已经完成独立质量验收。
- 人工补录成功也不能绕过仍在运行的执行占用或缺失的下游必要产物。

### R06. 取消、迟到结果与重试

- 时序以本地服务接受并持久化操作的顺序判定，不使用文件修改时间或页面时间猜测。
- 成功已提交为终态后，随后到来的取消无效，保留成功。
- 取消先被服务接受时，进入取消流程；之后收到的结果保留为迟到信息，不把任务自动改成成功。
- 中断已发送但执行尚未确认停止时，保持取消中；无法确认时进入待确认，不释放占用。
- 旧执行可能仍运行时，不自动启动重试，也不自动改派给其他 agent。
- 失败或取消后重试创建新的执行尝试，保留原说明及历史；需要改变已执行过的任务说明时，复制为新任务。
- 已成功任务再次执行使用“复制为新任务”，不覆盖原成功任务和下游引用。
- 取消不回滚文件修改，重试也不恢复干净环境。界面须说明重试在当前文件状态上进行。
- 需要全新环境时使用新的目录与会话；第一版不自动清理旧目录或提供通用回滚。
- 取消任务不关闭 herdr 窗格；中断 agent 不等于保证终止它启动的所有后台进程。

### R07. 队列推进

- 用户指定 agent，按创建顺序选取该 agent 队列中满足条件的任务。
- 前置条件未满足的任务不会阻塞其后的独立可执行任务。
- 派发条件包括：依赖满足、身份及状态可确认、允许自动调度、没有当前执行占用、没有未解决调度异常、全局并行额度可用。
- 明确的业务失败且 agent 已确认可用时，可以继续执行后续独立任务；失败任务的下游继续等待。
- 投递不明、身份变化、取消未完成和结果待确认等情况暂停该 agent 队列。
- 暂停调度仅阻止新派发，不中断当前执行。
- 不抢占运行中的任务，不自动改派，不因页面焦点或 herdr 的“已查看”状态改变业务结论。

### R08. 简单依赖及输入版本

- 第一版任务依赖在同一项目内建立，禁止自身引用和有向环。
- 尚未开始的任务允许修改说明、指派和依赖；开始执行后，本次输入冻结。
- 下游只有在所选前置任务成功且所需产物可用时才能派发。
- 派发时固定上游成功执行的标识、摘要和产物快照，不持续读取“最新结果”。
- 上游失败、取消或待确认时，不自动满足依赖；界面展示阻塞原因。
- 前置任务的失败重试成功后，可以重新评估尚未开始的下游；已经运行的下游不自动重跑。
- 新任务或新结果不会静默替换已运行下游的输入；使用新结果需要显式创建或安排新的下游执行。
- 被依赖引用的任务、执行和产物不能直接删除；归档不破坏现有引用。

### R09. 人工控制与审批

- 控制台内同一终端最多有一个有效网页输入控制方；多个页面可只读观察。
- 接管终端时暂停该 agent 后续派发；控制权冲突时提示用户，不自动强制抢占。
- 失去控制权的页面立即只读，其旧连接后续输入失效。
- 断线期间不缓存按键等待重连补发；终端关闭或 agent 身份变化后，旧页面不能继续输入。
- 只读页面不调整实际终端尺寸，输入控制方才能调整受控终端尺寸。
- 页面异常关闭后释放终端连接，调度仍保持暂停，等待用户显式恢复；关闭纯观察页面不影响调度。
- 释放输入控制权与恢复自动调度不是同一个动作，恢复时重新检查当前事实。
- 通过实时终端处理审批和追问，不依据旧画面发送批准，不在重连后重放审批按键。
- herdr 直接终端连接的单一控制方不等于覆盖原生客户端、API 和调度器的全局输入锁。

### R10. 工作目录、会话和数据归属

- 不同 agent 使用独立工作目录及会话，用户已确认这一级隔离。
- 同一 agent 可在同一项目内连续处理任务并保留上下文；不宣称每个任务都有全新上下文。
- 跨项目切换使用新的工作目录和会话，不能直接复用旧对话执行新项目任务。
- 输入、结果提交、归档和记录按执行尝试区分，不以 agent 名称作为产物存储身份。
- 下游输入使用上游归档的副本，保留来源，避免修改上游归档。
- 接入已有 agent 时，不符合隔离条件则保持观察模式，由用户建立符合条件的环境。
- 目录检查考虑真实路径、符号链接、父子目录重叠和共同输出位置，不能只比较路径字符串。
- 不同目录不保证隔离端口、数据库、Git 公共元数据或外部服务；使用共享资源的任务仍需显式安排，第一版不自动推断此类冲突。
- 同一系统用户下的 agent 仍可能访问其他目录；此隔离减少误覆盖和上下文串用，不防御恶意或越权 agent。

### R11. 产物采集、预览和归档

- 仅采集工作目录及本次任务明确授权输出范围内、最终结果显式列出的普通文件。
- 不能将任意绝对路径直接转换为可下载文件；检查真实路径、符号链接与路径穿越，不读取设备文件和管道等特殊对象。
- 设定文件数量、单文件大小及总归档体积限制，具体默认值在技术设计中确定。
- 采集期间文件变化、移动或删除时进入收集异常，不能把不完整产物提交为成功交付。
- 结果收集重试仅重试文件处理，不重新执行 agent 任务。
- 归档一旦发布给下游便不可变；原始工作文件后续修改不改变归档。
- 支持 Markdown、文本、JSON、图片预览及其他文件下载；预览不执行脚本、不自动加载外部资源。
- 超大文件不强行完整渲染，不提供任意本地文件读取或目录浏览能力。
- 磁盘不足时停止新派发、保留可恢复信息并展示原因，不能继续无记录地推进任务。

### R12. 断线、休眠和重启恢复

- 断线后立即标记观测过期，不使用旧空闲状态继续派发。
- 恢复时重新订阅事件并读取当前快照，核对执行身份、当前状态、本地执行记录和结果文件。
- 事件用于及时发现变化，恢复后的当前读取用于校准；不能让旧事件覆盖已经确认的新事实。
- 窗格变化后同步更新观测目标；不能只在首次启动时订阅当时存在的窗格。
- 结果目录需要恢复扫描，不能完全依赖运行时文件通知。
- 服务启动先恢复与核对，再开放调度；不直接重放未完成命令。
- 无法确认断线期间发生的事情时进入待确认，不推测成功或身份连续性。
- 持久化任务操作、观测到的状态变化、执行结果和产物；终端画面不是完整会话记录。
- 时间线标明观测缺口，不承诺补出全部历史终端输出、内部推理或不可恢复事件。

### R13. 超时、负载和存储异常

- 分别定义启动、投递确认、等待人工、结果收集、取消确认等超时的含义；具体阈值在技术设计中确定。
- 超时通常进入待处理，不自动等同业务失败，不自动重试。无输出不代表卡死。
- 终端大量输出与慢浏览器不得阻塞调度和结果持久化；不为所有 agent 无限缓存画面。
- 网页仅为正在查看的终端维持必要实时画面，不依赖页面保持打开来驱动调度。
- 提供本机并行任务上限，降低上限不强制终止已有执行。
- 数据存储不可写时停止新派发，尽力保留查看和人工中断能力，并明确展示无法持久化的操作。
- 电脑休眠后重新核对执行，不把休眠时间直接认定为 agent 卡死。
- 第一版不自动删除任务历史或被引用产物；容量清理必须可见、可控且不破坏引用。

### R14. 兼容、扩展和版本演进

- 分开定义 herdr 适配、调度、结果收集、终端连接和持久化的职责，不要求第一版实现插件平台。
- 业务状态不直接依赖 herdr 的展示文案；观察、投递、状态判断和结果交付分别判断支持能力。
- 启动时检查 herdr 版本和接口能力。以本机 0.9.0 为已检查基线，不依赖该版本没有的 `completion_seq`。
- 记录 session 归属，第一版仍只连接一个选定的本地 session。
- 结果协议、存储结构及以后形成的对外接口需要版本边界；未知版本不能静默按旧规则解析。
- 升级方案需要说明迁移、备份和恢复行为；恢复旧数据后先核对真实执行，不重放旧命令。
- 本地服务仅对本机开放，限制其他网站发起终端操作、任务修改和文件读取；产物预览遵守 R11。
- 首批操作系统、agent 类型、版本兼容矩阵及性能目标在技术方案中列明并实测，不能宣称自动兼容所有 herdr 支持对象。

## 5. 验收场景

下列是后续实现必须验证的场景，目前均未执行运行时测试。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| V01 | 从网页启动 agent，并完成有文件产物的任务 | 等待启动就绪、一次派发、结果匹配、归档成功、正确结束 |
| V02 | 接入手动启动的已有 agent | 不因缺少托管就绪标记永久阻塞；先观察，再完成归属及就绪确认 |
| V03 | 两个网页重复创建、派发或重试同一操作 | 只有一个有效操作和执行占用 |
| V04 | prompt 发出后服务在记录响应前崩溃 | 恢复后不自动重发，进入核对或待确认 |
| V05 | prompt 部分发送、超时或输入框残留内容 | 不以超时认定未发送，不盲目重试或清空用户输入 |
| V06 | agent 启动超时，但进程随后出现 | 不重复启动，重新核对实际状态 |
| V07 | 原生终端替换 agent、移动窗格或恢复旧会话 | 不把旧执行交给错误实例；身份不明时暂停 |
| V08 | agent 变为空闲但没有结果 | 不误报成功，展示缺失结果及处理入口 |
| V09 | 结果只写一半、属于旧执行，或产物尚未完整 | 不误报当前执行成功，不发布不完整产物 |
| V10 | 任务不需要文件产物 | 有效摘要和空产物列表可完成，不强制生成文件 |
| V11 | 成功提交与取消同时发生 | 按服务持久化接受顺序得到唯一结论 |
| V12 | 中断无效、旧执行可能仍运行 | 不释放占用，不重试或自动改派 |
| V13 | 重试后收到旧执行结果 | 保留旧记录，不覆盖新执行；不隐含回滚文件 |
| V14 | 某任务依赖未满足，后方存在独立任务 | 独立任务可推进；等待原因明确 |
| V15 | 明确业务失败与投递异常分别发生 | 前者可继续独立任务，后者暂停受影响队列 |
| V16 | 创建循环依赖或执行中修改已冻结输入 | 拒绝破坏依赖与执行版本的操作 |
| V17 | 上游重新执行或原始产物被修改 | 已运行下游使用的输入快照不变 |
| V18 | 两个页面接管、旧页面断线后发送按键 | 只有有效控制方可输入，旧输入不重放 |
| V19 | 审批已在原生终端处理，网页仍有旧画面 | 不根据旧画面自动批准，不复用过期交互 |
| V20 | 控制页面异常关闭、只读页面关闭 | 前者释放控制但保持调度暂停；后者不影响调度 |
| V21 | 两个 agent 使用重叠真实目录或同一会话 | 不启用独立自动调度，保持观察并说明原因 |
| V22 | 产物越界、符号链接绕过、特殊文件或超限 | 拒绝采集并给出明确原因，不越界读取 |
| V23 | 产物包含脚本、外部图片或超大内容 | 不执行脚本、不自动加载外部资源、不阻塞页面 |
| V24 | 休眠、事件丢失、本地服务或 herdr 重启 | 先核对身份、执行与文件，再恢复可确定的调度 |
| V25 | 磁盘满、存储不可写、终端输出暴增 | 不无记录地继续派发，调度与人工处理不被画面拖垮 |
| V26 | 本地服务被启动两次或多个页面同时在线 | 同一份数据仍只有一个派发者 |
| V27 | 未知协议版本或不支持的 agent 能力 | 明确拒绝或降级为观察，不静默采用错误规则 |
| V28 | 删除被下游引用的记录或产物 | 不破坏现有引用，归档后仍可追溯 |
| V29 | 其他网站尝试操纵本地服务或读取文件 | 操作被拒绝 |
